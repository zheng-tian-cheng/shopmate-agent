# ShopMate｜聊天滚动交互方案与验证计划

> **文档类型**：交互设计决策记录（Design Decision Log）＋可用性测试计划  
> **日期**：2026-11-02  
> **优先级**：P1（用户验证）；方案 D 已在当前原型中实现  
> **状态**：方案 D 暂行；A、B、C 作为对照方案保留，均未开展用户验证

## 1. 问题背景

在 ShopMate 的长对话中，用户可能一边阅读上一轮商品推荐，一边提前发出下一条问题。此时存在两种相互冲突的需求：

- **连续聊天**：希望发送消息后自动看到最新对话，不必手动下滑。
- **保持阅读**：希望新回复可以正常生成，但页面不要突然跳走，打断上一轮内容的阅读。

**设计目标**：在“快速看到新回复”和“不打断阅读”之间取得平衡，尽量减少额外操作。

## 2. 候选交互方案

| 方案 | 交互逻辑 | 优点 | 风险或代价 |
| --- | --- | --- | --- |
| **A｜自动跳转** | 用户发送消息、收到新回复时自动滚动到最新位置；不设置“回到最新消息”按钮 | 实现简单，连续提问顺畅 | 用户正在阅读旧内容时可能被突然带走 |
| **B｜手动查看** | 发送新消息不自动跳转；保留“回到最新消息”按钮，由用户决定何时查看 | 阅读位置由用户控制 | 新回复不够显眼，用户需要额外点击 |
| **C｜滑动感知** | 用户正在用手指或鼠标滑动时暂停自动跳转；没有检测到滑动时自动跳转；不设置“回到最新消息”按钮 | 尝试兼顾自动化与阅读保护 | **停止滑动不代表读完**，仍可能在阅读中被打断；判断和实现更复杂 |
| **D｜离开底部才暂停（当前采用）** | 用户停在底部时自动跟随新内容；用户主动往上滑、离开底部后暂停跟随，并显示“回到最新消息”按钮；滚回底部、点按钮或再次发送时恢复跟随 | 连续提问顺畅，看旧内容时不被新回复带走，随时一键回到最新 | 读到一半就发送时仍会跳到最新；用户可能没注意到按钮 |

### 方案 D 怎样结合 A、B、C

- **来自 A**：用户停在底部时自动跟随；发送消息后总是跳到最新内容。
- **来自 B**：保留“回到最新消息”按钮，让用户自己决定何时回到最新内容。
- **来自 C**：感知用户的滑动操作，但判断的是“用户有没有离开底部”，而不是“用户此刻有没有在滑”。用户停下手指后仍然保持暂停，避免了 C 的误判。

### 方案 D 的具体规则

| 场景 | 行为 |
| --- | --- |
| 用户发送消息（含快捷选项、重试） | 跳到最新内容 |
| 用户停在底部附近时，回复、推荐卡片或比较表出现 | 自动跟随，显示最新内容 |
| 用户主动往上滑（手指、鼠标滚轮、键盘、拖动滚动条） | 暂停跟随；新回复到达时页面不动；底部出现“回到最新消息” |
| 用户滚回接近底部、点“回到最新消息”或再次发送 | 恢复跟随 |
| 对话下方有很高的比较表 | 最新一轮停在顶部栏下方，比较表接在后面，避免最新回复被挤出屏幕 |

## 3. 当前决策及理由

**当前采用方案 D；A、B、C 保留为对照方案。**

- D 同时照顾了“连续聊天”和“保持阅读”两种需求，单独的 A、B、C 都只照顾了一部分。
- D 已经在当前原型中实现，不阻塞购物条件理解、筛选、比较和推荐解释等核心能力的验证。
- 现阶段缺少真实用户证据，D 只是暂行方案，后续测试需要重点关注它的两个风险：发送时跳转是否让人觉得被打断，以及用户是否注意到“回到最新消息”按钮。

> **决策边界**：采用 D 不等于已经证明 D 最优；它是基于现有理解的综合方案，仍需用户验证。

## 4. 待验证假设

- **H1**：连续提问时，方案 D 和 A 一样，用户不需要额外操作就能看到新回复。
- **H2**：阅读旧内容时，方案 D 比 A 更少出现意外跳转。
- **H3**：仅根据“是否正在滑动”判断阅读状态（方案 C）会造成误判；改为判断“是否离开底部”（方案 D）误判更少。
- **H4**：用户读到一半就发送新问题时，跳到最新内容符合预期，不会让人觉得被打断。

## 5. 后续可用性测试计划（P1）

**方法**：先对约 5 名目标用户开展探索性可用性测试，手机和桌面都要覆盖；不把小样本结论当作统计显著的 A/B 测试结果。

**任务 1｜连续提问**：让用户连续询问两款耳机的价格、续航和区别，观察是否容易跟上新回复。

**任务 2｜等回复时看旧内容**：用户发送问题后、回复出来前，往上翻看上一轮推荐，观察是否被新回复打断，以及能否顺利找到新回复。

**任务 3｜读到一半就提问**：让用户阅读一段含商品卡片的长回答，并在读完前发送下一条问题，观察发送后的跳转是否让人觉得被打断，以及能否回到原来的阅读位置。

**观察指标**：

- 意外跳转或阅读中断的次数；
- 找到新回复所需的额外操作；
- 是否注意到并使用“回到最新消息”按钮；
- 是否能轻松回到原来的阅读位置；
- 用户对“打断感”和“操作方便程度”的主观评价。

**判定方式**：综合观察结果和访谈反馈决定是否迭代。若用户主要抱怨发送后被带走，考虑发送时也不自动跳转（向 B 靠拢）；若主要抱怨找不到新回复，优先让新消息入口更醒目，例如提示“有新回复”。暂不预设最终方案。

> **说明**：当前原型只实现了方案 D。如需让同一批用户对比 A、B、C，需要先在原型中增加方案切换开关（尚未实现）。

## 6. 与现有 PRD 的关系

- **当前 MVP**：采用方案 D，不因该问题阻塞核心购物流程。
- **P1 待验证**：用户测试验证方案 D，必要时与 A、B、C 对比。
- **P2 可选优化**：更细致的滚动动画、“有新回复”提示等。
- **已实现、待真机验证**：手机键盘弹出时，聊天面板贴合可见区域，避免遮住输入框和最新消息；重新打开助手时回到上次的阅读位置。目前只在模拟环境中测试过，尚未在 iPhone 和 Android 真机上验证。

**面试展示价值**：该记录体现了从真实使用中发现体验矛盾、提出不同方案、综合成可落地的方案，并将未经验证的设计判断转化为可用性测试计划的过程。
