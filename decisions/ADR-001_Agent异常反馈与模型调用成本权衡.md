# ADR-001｜Agent 异常反馈与模型调用成本权衡

| 项目 | 内容 |
| --- | --- |
| 所属项目 | ShopMate — AI 交互式购物助手 |
| 决策类型 | 架构与产品交互决策（Architecture Decision Record） |
| 日期 | 2026-11-02 |
| 状态 | **已完成、已验收**（依据项目方确认） |
| 关联模块 | Gemini Agent、FastAPI 条件校验、会话状态、聊天界面 |
| 关联需求 | 购物需求理解、条件变更、异常反馈、推荐内容呈现 |

## 1. 背景与问题

在 ShopMate 的真实 Agent 对话中，用户提出近似“600 元左右、酷炫动感的耳机”的需求。系统能够检索并展示商品，但同时暴露了若干问题：

- 条件变更详情出现“**条件类别与字段不匹配**”等内部校验信息，用户无法判断具体哪些要求未被处理。
- 模型生成的文字清单与前端商品推荐卡片重复，增加阅读负担。
- 回复中曾出现 `¥¥599元` 等货币格式重复。

这不仅是文案问题，还涉及 **语义理解、业务校验、异常状态反馈和模型调用成本** 的边界划分。尤其要避免两种相反的错误：一是把内部错误原样展示给用户；二是隐藏错误后让用户误以为全部需求已被处理。

## 2. 决策目标

1. 让用户知道哪些购物条件已经生效，以及哪些重要需求仍未处理。
2. 保留后端对参数、条件类别、状态和业务规则的确定性校验。
3. 区分“模型提交了非法工具参数”与“用户表达了暂时无法结构化的真实需求”。
4. 不为解释每次异常额外发起一次独立的 LLM 请求，控制额外等待和推理成本。
5. 避免商品正文、卡片与金额格式重复；维持现有购物闭环。

## 3. 方案比较

| 方案 | 优势 | 代价与风险 | 决策 |
| --- | --- | --- | --- |
| A. 直接隐藏异常信息 | 改动小，界面简洁 | 可能掩盖未处理的用户需求 | **不采用** |
| B. 每次异常额外调用 LLM 生成解释 | 表达灵活，解释可能更自然 | 增加模型请求、延迟和解释不准确的风险 | **不采用** |
| C. 程序校验与结构化反馈，LLM 在既有回复流程中处理语义歧义 | 准确性边界清晰，减少不必要的额外调用，保留自然对话 | 需要明确错误类别和未解决需求的状态 | **采用** |
| D. 为异常反馈引入独立 Agent 或复杂工作流 | 可扩展性较强 | 超出当前 MVP 的问题规模，增加实现与维护成本 | **不采用** |

## 4. 最终决策与处理流程

采用 **“Gemini 理解需求 + FastAPI 校验执行 + Agent 汇总结果 + 现有回复流程解释”** 的混合方案。

1. **理解需求**：Gemini 尝试识别用户的品类、预算、硬性条件、软偏好和使用场景；对“酷炫”“动感”等描述保留语义上的不确定性，不直接伪装成确定的商品属性。
2. **提出操作**：Agent 根据模型的工具调用请求，将可结构化的条件提交给现有后端业务函数。
3. **校验与执行**：FastAPI 对条件类别、字段、数据类型和用户确认权限进行校验；返回成功变更与结构化拒绝原因。
4. **保留未解决需求**：无法对应当前筛选字段的用户偏好不应当作已生效条件，也不应在后续对话中无故丢失。工具参数错误与不支持的语义需求分开记录。
5. **生成反馈**：确定性成功提示或常见错误可由程序直接呈现；真正需要理解用户含义时，Gemini 利用**原有本轮回复流程**进行解释或必要澄清，而不是额外启动一次“错误解释”调用。
6. **呈现商品**：商品名称、价格和参数以结构化商品数据及卡片为准；自然语言回复侧重简洁引导，不重复罗列卡片，也不重复货币符号。

**关键边界：** FastAPI 判断操作是否合法，LLM 负责理解表达和组织自然语言。LLM 不能因为提出了某个条件，就声称后端已经执行成功；未经过证据支持的偏好不能被描述为已参与商品排序。

## 5. 成本、效果与取舍

本决策避免了“每遇到一条校验错误，就单独调用一次大模型解释”的设计。对于后端已经确定的结果，直接使用程序化反馈通常更可控，也不会产生专门的解释请求。

这是一项**避免不必要调用的设计选择**，而非已量化的成本节省结论。本记录不虚构调用次数减少比例、响应速度提升或人民币成本节省值；真实成本还取决于异常发生率、模型调用链及运行环境。

同时，不以降低模型调用数为由牺牲关键需求的准确性：如果用户的模糊要求影响推荐适用性，系统仍应在正常对话中澄清，而不是简单忽略。

## 6. 实施与验收结论

**状态：已完成、已验收（项目方确认）。**

本次决策所对应的实现与验收围绕以下约束收口：

- 不直接向普通用户暴露内部字段、Schema 或工具校验术语。
- 不把失败操作显示为成功，也不删除此前已经合法生效的条件。
- 区分非法工具参数与无法结构化的真实用户偏好。
- 不为异常解释增加独立的 LLM 调用链路。
- 推荐正文与商品卡片分工明确，价格和货币格式统一。
- 保留原有商品筛选、确认同步、硬约束及聊天滚动能力。
