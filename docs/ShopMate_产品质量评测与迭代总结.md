# ShopMate｜产品质量评测与迭代总结 V0.5

> 2026-11-03 · 面试展示版｜B0 基线、RAG 技术实验与 RAG1 回归均已完成

## 一、为什么做评测？

ShopMate 能根据需求推荐商品，但初版的商品卡片主要展示基础信息，**缺少不同商品的具体优势、使用限制和购买取舍**。因此，我们提出一个改进方向：用可追溯的商品资料增强推荐解释。

评测不是为了证明“用了 RAG”，而是回答三个问题：**原产品哪里容易出错？什么技术方案值得采用？接入后是否真的回答得更好？**

为此，建立了 **3 道购物条件题、5 道商品问答题、1 个四轮购物任务**的产品评测集，并用 **17 道固定查询**评估商品证据检索。

## 二、评测驱动的改进过程

| 阶段 | 做了什么 | 得到了什么 |
|---|---|---|
| **B0：发现问题** | 测试没有 RAG 的 ShopMate | 发现 LHDC 兼容性解释不完整、降噪指标口径混淆等 Bad Case |
| **A/B/C：技术选型** | 对比普通切分、DOM 结构化切分、混合检索 | 结构化切分明显改善证据召回；混合检索未带来明显回答收益 |
| **B+：针对性优化** | 按规格组切分，按商品分别检索并均衡组织证据 | 降低多商品比较时的证据偏向，提升固定查询的上下文覆盖 |
| **RAG1：产品验证** | 将证据检索接入真实 Agent，复测原有题目 | 一项典型事实错误得到纠正，也发现生成和校验环节仍有问题 |

## 三、关键结果

**技术层：17 道固定检索查询**

| 指标 | 普通切分 A | 结构化切分 B | 产品方案 B+ |
|---|---:|---:|---:|
| Recall@5 | 0.588 | 0.809 | **0.912** |
| Hit@1 | 7/17 | 12/17 | **14/17** |

混合检索 C 的 Recall@5 为 0.838，但最终回答没有明显额外收益，因此没有把 BM25 + RRF 作为默认方案。

**产品层：B0 与 RAG1 的固定用例对照**

| 结果 | B0 | RAG1 |
|---|---:|---:|
| 商品问答通过 | 0/5 | **1/5** |
| 商品问答严重错误 | 1 次 | **0 次** |
| 购物条件题通过 | 0/3 | 0/3 |
| 完整购物任务 T01 | 未达标 | 未达标 |

**最明确的改进是 RAG-05：** 原来把华为的 **27dB 平均降噪深度**误写成最大值；接入证据后，能区分它与一加的**最高 49dB**，并说明两者不能直接比较。该题由 **2/6 提升至 5/6**。

## 四、评测还发现了什么？

- **RAG-02：检索改善，不等于建议改善。** 固定检索查询中，两款耳机的必要证据召回更完整；但实际对话会受到模型检索措辞影响，最终回答仍为 **4/6**，没有稳定回答“值不值得为 LHDC 加钱”。
- **T01：推荐解释仍不充分。** 多轮购物任务依旧未达标，商品理由重复，对续航偏好变化缺少实质回应。这也说明最初发现的“推荐缺乏差异化”尚未得到解决。
- **校验规则也会影响体验。** 过严的数字引用限制曾拦截有依据的回答，说明需要同时平衡事实可靠性与回答完整性。

## 五、项目结论

这轮迭代形成了**产品观察 → B0 定位问题 → 技术对照与取舍 → RAG 集成 → 产品回归验证**的闭环。

**已取得的成果：** 提高固定测试集的证据召回，纠正一项典型的商品参数解释错误，并建立可复现的评测与问题定位流程。

**仍需解决的产品问题：** 跨商品比较的回答稳定性、推荐理由差异化，以及多轮购物任务的完成质量。

> 数据来自小规模固定测试集，适合说明本轮迭代效果，不代表整体购物体验或真实转化率的提升。新版本还包含 Prompt 和回复校验调整，效果不应全部归因于 RAG。
